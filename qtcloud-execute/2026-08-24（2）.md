# CEO 办公室任务机制 v0.1

> 日期：2026-08-24
> 整理：员工C
> 目的：解决「传话失真 / 优先级混乱 / 任务静默卡住 / 老板靠催才知道进度」的管理问题
> 落地载体：执行云（execute.cloud.quanttide.com）

***

## 一、我们面对的问题

### 老板的原话（2026-08-24 CEO 办公室群）

> 目前看，我们管理上的问题主要是优先级混乱。今天就有两个卡点：
>
> 1. 跟员工A传话的时候说我这边备一个方案，我都紧急联系了，为什么会是备一个方案呢？
> 2. 员工B跟员工A在沟通「沟通云」和「发招聘邮件」的顺序时，明显出现了卡点，就是因为在等「沟通云」的进度，导致发邮件卡住了。
>    咱们传事情一定要传清楚优先级，或者是一定要判断清楚优先级。

### 诊断

- **任务的生命周期没有被承载**：老板发消息 → 大家收到 → 开始执行 → 过程消失 → 到时间才发现没完成。邮件管通知、聊天管沟通，但没人管「事情现在到哪了」。
- **传话失真**：信息每多中转一层，就失真一分。而且中转人（CEO 办公室）在「理解→转述」时，容易对指令做加工降级（把「紧急联系」听成「备一个方案」），导致错误在中转时发生、且不可见。
- **靠人催**：老板必须亲自问才能知道进度，等于老板替系统承担了「追踪」职能。

***

## 二、核心思路：让执行透明，老板只做校对

四层，一层层补上：

| 层级    | 机制                      | 作用            |
| ----- | ----------------------- | ------------- |
| ① 源头  | 任务都是老板想的，我们只负责「翻译 + 发布」 | 明确职责边界        |
| ② 校正点 | 发布任务卡时，卡片贴回群里让老板扫一眼纠错   | 理解错了当场改，错不落地  |
| ③ 透明  | 过程留痕，老板随时可查             | 不用汇报，不占老板时间   |
| ④ 减决策 | 正常静默，异常才报               | 老板只在值得介入的节点出现 |

**一句话**：不是让老板少知道，而是让他「低成本地知道 + 只在必要时才被叫到」。

类比：外卖订单。下单后不用盯着骑手，但打开 App 随时能看进度（透明）；只有超时才推送提醒（异常通知）。不被刷屏，也不失联。

## 三、任务卡

### 字段（第一版，够用即可）

| 字段    | 内容                                       |
| ----- | ---------------------------------------- |
| 任务名称  | 一句话说清做什么                                 |
| 任务编号  | CEO-YYYYMMDD-NNN                         |
| 优先级   | P0（紧急/外部/阻塞他人）/ P1 / P2                  |
| Owner | 唯一负责人                                    |
| 协作人   | 参与的人                                     |
| 来源    | CEO 办公室                                  |
| 截止时间  | 硬截止                                      |
| 当前状态  | 🟢 未开始 / 🟡 进行中 / 🟠 有风险 / 🔴 卡住 / ⚪ 已完成 |
| 下一步动作 | 下一件具体要发生的事 + 负责人 + 预计完成时间                |
| 卡点    | 现在有什么东西阻止它往前                             |
| 节点    | 时间节点表（见第四章）                              |

### 示例：招聘邮件

```
【P0】招聘邮件发送
任务编号：CEO-20260824-001
Owner：员工A   协作人：员工B
截止：今天 16:00
状态：🟡 进行中

节点：
| 节点     | 时间          | 状态  |
|----------|--------------|-------|
| 名单确认 | 8月24日 14:00 | 进行中 |
| 内容定稿 | 8月24日 15:00 | 待完成 |
| 邮件发送 | 8月24日 16:00 | 待完成 |

下一步：等待员工B 14:00 前确认最终名单
卡点：无（若 14:00 未收到名单，按现有名单先发第一批）
```

## 四、节点怎么设

### 三步拆法

1. **先定终点**：这个任务做完长什么样？
2. **找「必须停下来看一眼」的环节**：从开始到终点，哪些环节过不去后面就动不了？——等别人（外部依赖）、交接到别人手上、有硬截止、容易出错要检查。
3. **切开，标时间 + 产出 + 负责人**。3\~5 个节点，宁少而准。

**规则**：

- 节点设在哪，不看均匀，看「哪里可能卡住」。
- 时间预估保守，宁松勿紧。太紧天天变红 → 红黄绿失效（狼来了）。

### 分工：谁设节点

> **节点由「知道哪里会卡住的人」来设。**

| 角色           | 职责                   |
| ------------ | -------------------- |
| 老板           | 校对卡片 + 只看异常          |
| CEO 办公室（发布者） | 发布、**问**节点、校验三件套、追红灯 |
| 执行人（Owner）   | **设自己的业务节点** + 点亮状态  |

发布者不需要懂业务，但每次发布前校验「三件套」：**截止时间、Owner、下一步**。业务节点用三个问题问出来：

1. 这活做到哪一步，算「有实质进展」了？
2. 中间要等谁？哪里容易卡？
3. 预计什么时候完成？

执行人口述，发布者代笔。**发布者的价值是「会问、会记、会校对」，不是「知道」。**

### 保证更新：到点不点亮就报警

节点到时间没人点亮 → 自动转黄 → 再拖转红。
「更新」不靠执行人自觉，靠「不点亮就亮灯」——系统替你和老板盯着。

***

## 五、三档分工总览

- **老板**：任务发布时扫一眼卡片纠错；之后只在红灯（卡住/超时/需决策）时介入。
- **CEO 办公室（员工C）**：发布任务卡、问节点、校验三件套、追红灯、协调卡点。
- **执行人**：设自己的业务节点、点亮状态、暴露卡点。

老板的角色从「下达者」升级为「校对者」：只在值得的节点介入，其余系统自动跑。

## 六、落地到执行云

### 现有执行云现状（2026-08-24 确认）

定位：「让执行从靠人记得，变成靠系统看清」。三大模块：

- **看清**：二维看板、状态泳道，要做什么不做什么一眼看清
- **推进**：拖拽推进状态、即改即存，改一下就是推进
- **提炼**：AI 从日志提炼任务、人确认，你不记得的系统替你记得

本质是**个人任务看板**——解决「人忘记任务」。任务都是自己的，没有负责人、没有老板/组织视角。

### 与现有执行云的差异（这套机制要补的）

| 维度       | 现有执行云          | CEO 机制补的                   |
| -------- | -------------- | -------------------------- |
| 视角       | 个人「我的任务」       | 组织「全公司任务」                  |
| 核心问题     | 人忘记任务          | 组织不知道进度 / 谁卡住              |
| 状态       | 规划中 / 进行中 / 完成 | 红黄绿（正常/风险/阻塞），卡住被显性化       |
| 负责人      | 无              | Owner 唯一负责人                |
| 下一步      | 无              | Next Action（必须能答「下一件具体动作」） |
| 卡点       | 无              | Blocker（什么东西阻止它往前）         |
| 优先级      | 无              | P0 / P1 / P2               |
| 截止时间     | 无              | Deadline 硬节点               |
| 时间节点     | 无              | 节点表 + 到点不点亮自动黄→红           |
| 依赖 / 等回复 | 无              | 等待被产品化，超时自动暴露              |
| 老板视角     | 无              | 发布时校对 + 只看红灯 / 需决策 / 需协调   |
| 推进定义     | 拖一下就算推进        | 有有效推进事件才算推进（时间线）           |
| AI 角色    | 从日志提炼任务        | 发现执行异常（超时 → 建议干预）          |

一句话：现有执行云「靠人记得 → 靠系统看清」；CEO 机制「靠人催 → 靠系统推进」。

### 升级路径

现有「看清 / 推进 / 提炼」全部保留，只需补执行云现在没有的三样：**Owner、Next Action、Blocker**，加上红黄绿和节点报警，从「个人看板」升级为「组织执行系统」。

任务不止「待办→进行中→完成」，而是：

**任务产生 → 明确责任 → 开始执行 → 持续推进 → 异常暴露 → 协调解决 → 完成闭环**

每个任务永远回答三个问题：

- **Owner**：谁对此负责？
- **Next Action**：下一步具体要发生什么？
- **Blocker**：现在有什么东西阻止它继续往前？

管理视图：

```
今日任务 27
🔴 3 个阻塞
🟡 4 个风险
🟢 16 个正常
⚪ 4 个完成
```

老板第一眼只看红色的。再看「需要我决策」「需要我协调」两项。

**验证指标**（内部跑两周）：

1. 老板主动问进度的次数 ↓
2. 任务静默延期次数 ↓
3. 真正需要老板拍板的次数 ↓
